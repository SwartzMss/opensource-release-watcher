# 前端设计

本文记录前端页面职责、关键交互和状态展示规则。API 字段以 [API 与字段契约](api-contract.md) 为准。

## 1. 页面结构

| 页面 | 目的 |
| --- | --- |
| 仪表盘 | 展示系统概览、运行状态和最近组件版本动态 |
| 组件管理 | 维护组件清单，触发单组件检查 |
| 漏洞检查 | 查看组件当前版本的漏洞状态和漏洞明细 |
| 订阅人管理 | 维护收件人和订阅范围 |
| 检查记录 | 查看版本检查历史 |
| 通知记录 | 查看邮件发送历史和正文快照 |

## 2. 仪表盘

核心卡片：

- 组件管理：组件总数。
- 组件更新：当前存在上游新版本的组件数量。
- 漏洞检查：当前命中漏洞的组件数量。
- 检查异常：最近检查失败数量。
- 通知异常：邮件发送失败数量。

系统概览：

- 代理设置。
- GitHub Token。
- 调度状态。
- 最近检查时间。
- 邮件功能。

代理和 GitHub Token 状态来自后端缓存，页面刷新不会触发实时网络探测。

组件版本动态：

- 展示最近有更新的检查记录。
- 通知状态优先按 `run_id` 匹配，其次按 `check_record_id`，最后按 `组件 + 最新版本` 兼容历史数据。
- 漏洞风险来自组件最新安全状态。

## 3. 组件管理

列表展示：

- 组件名称。
- GitHub 仓库。
- 当前版本。
- 最新版本。
- 是否启用。
- 最近检查状态。
- 最近检查时间。
- 漏洞风险。

编辑规则：

- `repo_url` 创建后不可编辑。
- `current_version` 只允许向前升级。
- `current_version` 需要能在 GitHub Release / Tag 中解析。
- 编辑表单只维护组件基础信息，不展示漏洞概要。

操作：

- 新增组件后立即触发一次组件检查。
- 更新组件后立即触发一次组件检查。
- 手动检查按钮触发单组件检查。

## 4. 漏洞检查

列表按组件聚合展示当前安全状态。

字段：

- 组件名称。
- 当前检查版本。
- 漏洞状态。
- 漏洞数量。
- 漏洞编号。
- 建议升级版本。
- 最近检查时间。

详情区：

- 组件概览。
- 漏洞编号列表。
- 单个漏洞摘要、严重性、建议升级版本和 OSV 链接。

展示规则：

- `affected` 显示“有漏洞”。
- `unknown` 显示“未识别”。
- `check_failed` 显示“检查失败”。
- 修复版本是 commit hash 且未解析成版本号时，界面展示 `-`。

## 5. 订阅人管理

订阅人支持两种范围：

- 全部组件。
- 指定组件。

交互规则：

- 开启“订阅所有模块”后，模块选择区域只读。
- 关闭后恢复指定组件选择。
- 删除订阅人时，后端同步清理该邮箱的通知记录和订阅进度。

## 6. 检查记录

用于查看版本检查历史。

核心字段：

- 组件。
- 检查运行 ID。
- 数据来源。
- 检查前版本。
- 最新版本。
- 是否存在更新。
- 状态。
- 错误信息。
- 检查时间。

操作：

- 查看 Release Note 摘要。
- 打开 GitHub Release / Tag 链接。
- 按组件、状态、是否有更新筛选。

## 7. 通知记录

用于查看邮件发送历史。

核心字段：

- 组件。
- 检查运行 ID。
- 通知类型。
- 通知版本。
- 收件人。
- 发送状态。
- 失败原因。
- 发送时间。

详情展示邮件正文快照。

筛选条件：

- 组件。
- 收件人。
- 通知状态。

## 8. 移动端

移动端优先使用卡片展示表格信息。

要求：

- 核心列表信息可读。
- 常用操作可点击。
- 弹窗宽度适配小屏。
- 长文本使用省略或详情展开。
