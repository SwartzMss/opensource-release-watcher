# 文档索引

`doc/` 存放项目的产品需求、实现设计和字段契约。根目录 `README.md` 只保留项目入口、使用方式和常用配置。

## 文档职责

| 文档 | 用途 |
| --- | --- |
| [产品需求](requirements.md) | 产品目标、核心场景、功能范围和非功能要求 |
| [后端设计](backend-design.md) | 后端模块职责、检查流程、通知策略和运行状态检测 |
| [前端设计](frontend-design.md) | 页面职责、交互规则和展示逻辑 |
| [API 与字段契约](api-contract.md) | HTTP API、请求响应字段和枚举值 |
| [数据模型](data-model.md) | SQLite 表结构、字段含义和索引约束 |
| [安全风险设计](security-risk-design.md) | OSV 查询、风险判定和修复版本建议逻辑 |

## 维护原则

- README 面向使用者，避免展开实现细节。
- 需求文档描述“系统做什么”，避免写具体代码结构。
- 设计文档描述“系统怎么做”，避免重复 API 字段和数据库表结构。
- API 和数据模型以当前实现为准，字段变化时优先同步这两个文档。
- 安全风险设计用于解释漏洞检查的判定边界和证据来源。
